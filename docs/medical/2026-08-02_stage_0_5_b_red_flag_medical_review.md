## 1. この資料の目的

本資料は、NAOMIが体調に関する入力を受けた際に、通常の状態整理問診を続けてよいか、それとも問診を停止して人へ引き継ぐべきかを、医療専門家にレビューしてもらうためのたたき台である。

ここで行うのは、公式資料の記載とNAOMI向け設計仮案の分離、未確定事項の列挙、レビュー用テスト期待値の準備までである。診断、重症度の確定、治療・応急手当の指示、医学ルールの実装は行わない。

### 1.1 用語

- **[公式資料要約]**: 下記の消防庁・厚生労働省資料について、本資料が要約した内容。医学的妥当性と正確なロケータは専門家確認待ち。
- **[NAOMI設計仮案]**: 公式資料要約をNAOMIの会話UIへ適用するための暫定案。医学的に未承認。
- **[専門家判断待ち]**: CodeXでは確定せず、医療専門家の承認・修正・保留判断を必要とする内容。
- **Human Handoff**: 自動問診を停止し、119、地域の救急電話相談、医療機関、またはその場の支援者など、人が判断する経路へ移すこと。
- **Red Flag Gate**: Stage 1実装へ進む前の承認点。医学的妥当性と運用上の安全性の双方を確認する。

## 4. 公式資料に書かれている内容

**[公式資料要約]** この節の公式資料に関する説明は要約であり、NAOMIの確定仕様ではない。各要約の医学的妥当性とロケータは専門家確認待ちである。

### 4.1 緊急度と対応は分けて考える

**[公式資料要約]** 消防庁の救急受診ガイドは、緊急度を「病気やけがが重症化していく速さ」と説明している。Q助は必要な対応を次の4段階で示す。

1. 今すぐ救急車を呼ぶ
2. できるだけ早めに医療機関を受診する
3. 緊急ではないが医療機関を受診する
4. 注意して様子を見る

**[NAOMI設計仮案]** 単一の`red_flag=true/false`だけでは、緊急度、推奨経路、判定不能を十分に表現できない可能性がある。

### 4.2 主訴より先に共通の生命危機確認がある

**[公式資料要約]** 家庭自己判断ガイドおよび電話相談プロトコルでは、個別症状へ進む前に、次のような共通確認を置いている。

- 呼吸がない、脈がない、心臓が止まっている、水没、身体が冷たいといった心肺停止に強く関連する情報
- 呼びかけへの反応
- 普段どおり話せるか、声が出るか
- 呼吸が苦しそうか
- 顔色、唇、耳の色、冷や汗
- しっかり受け答えできるか

**[公式資料要約]** 電話相談プロトコルでは、一部の異常は119番転送とされ、呼吸・意識の異常は対応する高緊急度プロトコルへ移る。

### 4.3 高い緊急度から先に確認し、該当後は下位質問を続けない

**[公式資料要約]** 電話相談プロトコルは、緊急性の高い質問から順に確認し、上位カテゴリが否定された場合に下位へ進む構造である。「赤」に該当した場合は、それより下位の質問へ進む必要はないとしている。

**[NAOMI設計仮案]** 「Red Flag確認を通常問診より前に置く」「停止条件成立後に状態整理質問を続けない」という構造を仮置きする。

**[専門家判断待ち]** 具体的な質問文と分岐は、専門家レビュー前に確定しない。

### 4.4 厚生労働省が示す119要請例

**[公式資料要約]** 厚生労働省ページには、成人では突然の激しい頭痛、急な呼吸困難、一定時間続く締め付け・圧迫様の胸痛、突然の片側の脱力、吐血・血便・黒色便などが例示されている。子どもでは、呼吸が弱い、呼吸が苦しそう、止まらない嘔吐、水分が取れず意識がはっきりしないなどが例示されている。高齢者向けにも、突然の頭痛、急なふらつき、急な呼吸困難、片側の脱力などが示されている。

**[NAOMI設計仮案]** これらの例示をNAOMI用の完全な判定集合として扱わず、例示にないことだけを理由に安全とはみなさない。

### 4.5 年齢・相談対象者・既往歴等は引継ぎ情報でもある

**[公式資料要約]** 電話相談プロトコルは、本人通報か、相談対象者のそばに行けるか、年齢、性別、主訴を共通項目で確認する。小児用プロトコルは概ね15歳以下、高齢者は65歳以上としている。

**[公式資料要約]** 厚生労働省の119案内では、年齢、性別、普段どおりの呼吸・会話、冷や汗、顔色、症状のほか、持病、かかりつけ医、普段の薬、医師の指示等を伝える項目としている。

**[NAOMI設計仮案]** 年齢、既往歴、服薬の確認を理由に、明白な緊急状態でのHandoffを遅らせない構造を仮置きする。

### 4.6 判定に迷うときは人へつなぐ経路がある

**[公式資料要約]** #7119は、救急車を呼ぶか、今すぐ受診するか迷う場合に、医師・看護師・救急救命士から助言を受ける仕組みである。緊急性が高いと判断した場合は119への転送やかけ直し要請が行われる。対象年齢、実施地域、利用時間は地域により異なる。子どもについては#8000も案内されている。

**[NAOMI設計仮案]** NAOMIは#7119や119の代替とせず、地域・時間が未確認のまま、常に#7119が利用できるような表示をしない。

## 6. NAOMI向け設計仮案

**[NAOMI設計仮案]** この節はすべて未承認の設計仮案である。医学的分岐は専門家判断待ちとする。

### 6.1 Gateの位置

```text
入力受付
  -> 最小限の対象者・応答可能性確認
  -> Red Flag共通確認
       -> 明白な緊急: 問診停止 -> 119 Human Handoff
       -> 判定不能/曖昧: 問診停止または確認1問 -> 有人相談 Human Handoff
       -> 上位緊急性を否定: 通常の状態整理問診へ
```

Red Flagは、Intakeの15項目を順番に聞く途中機能ではなく、各入力ターンで通常問診より先に評価する。停止後はSummary Confirmationや残りの問診を続けない。

### 6.2 暫定出力クラス

医学的内容ではなく、状態機械の出口として次を仮置きする。

| 暫定クラス | 動作仮案 |
|---|---|
| `STOP_119` | 問診を即時停止。119への連絡を明確かつ短く案内する。追加の医学質問をしない。可能なら近くの人へ助けを求める選択肢を示す。 |
| `STOP_HUMAN_URGENT` | 問診を停止。地域の有人救急相談、医療機関、現場スタッフ等へ引き継ぐ。利用可能な窓口を地域・時間未確認のまま断定しない。 |
| `ASK_ONE_CONFIRMATION` | 高緊急度を安全に否定できず、本人に回答能力がある場合だけ、承認済みの確認質問を1問出す。 |
| `CONTINUE_INTAKE` | 承認済みの上位確認が否定され、通常問診を続けてよい状態。これは「安全」「軽症」「診断不要」を意味しない。 |

### 6.3 画面・会話の仮案

- 119相当時は、共感文を長くせず、最初の画面内に行動を表示する。
- 「様子をみてください」とNAOMIが独自に断定しない。
- Handoff後は質問ボタンを無効化し、利用者が明示的に戻すまで通常問診へ復帰しない。
- 自動発信は実装しない。発信ボタンを置く場合も、ユーザー操作と利用環境の確認を前提にする。
- Red Flag判定と確認質問は、承認済みルールによるローカルの決定論的処理とし、医療入力をGemini、Agent Engine、Arize等の汎用クラウド経路へ送らない。
- Handoff Noteには、診断名ではなく、本人が述べた内容、発症時期、変化、確認済み/不明、理由コードを記録する。
- Handoff Noteでは、本人発言、入力上確認できた事実、対話制御上の状態、未確認事項を混ぜず、未回答を推測で補完しない。
- 住所、氏名、電話番号等はNAOMIの監査ログへ残さない。119通報で必要な情報は、指令員へ直接伝えるよう案内する。
- 判定不能時は「危険」「緊急」と診断的に断定せず、「今の情報だけでは安全に整理を続けられないため、人に確認してもらえる形へ切り替えます」という趣旨の承認済み固定文を使う。

## 7. 問診を停止してHuman Handoffへ進む条件（仮案）

**[NAOMI設計仮案]** この節のHandoff条件は、公式資料要約を参照して構成した未承認案である。

**[専門家判断待ち]** 条件、文言、組合せ、閾値、確認質問、Handoff先を本資料では確定しない。

### 7.1 `STOP_119`候補

**[公式資料要約]** 次の一部に対応する119または即時転送の例が公式資料にあると本資料では要約している。正確なロケータは未確認である。

**[NAOMI設計仮案]** これらをNAOMIの停止候補として仮置きする。ただし正確な文言・組合せ・閾値は専門家判断待ちとする。

- 呼吸がない、脈がない、心臓が止まっているとの申告
- 呼びかけに反応しない、普段どおり話せない、声が出ない
- 急な呼吸困難、明らかな呼吸異常
- 明らかな顔色・唇色の異常、冷や汗等と急性症状
- 突然の激しい頭痛、脳卒中を疑う片側の脱力やろれつ異常
- 締め付け・圧迫様の胸痛など、公式資料が119例として示す胸部症状
- 吐血、血便、黒色便、突然または持続する激しい腹痛
- 子どもの弱い呼吸、重い呼吸苦、意識がはっきりせず水分が取れない状態
- 相談者自身が119を求めている、または現場で明らかな生命危機が伝えられている

### 7.2 `STOP_HUMAN_URGENT`候補

**[NAOMI設計仮案] [専門家判断待ち]** 次の候補は、公式資料が直接規定した条件として扱わず、専門家レビュー対象とする。

- 高緊急度確認への回答が「不明」「判断できない」「見ていない」
- 入力が矛盾し、否定・肯定のどちらか安全に確定できない
- 本人が会話を続けられない、入力能力が急に低下した、`response_capacity`が不足している
- 強い`overload`により確認質問へ安全に答えられない
- 相談者と傷病者が別で、対象者の状態を直接確認できない
- 複数の高緊急度主訴がある、または途中で新たな高緊急度主訴が出た
- 年齢、妊娠・妊娠可能性、既往歴、服薬が判断を変え得るが、承認済みルールで扱えない
- ユーザーが有人対応を希望する
- システムが判定に必要な文脈を失った、または内部エラーで安全確認を完了できない

### 7.3 Handoff後にしてはいけないこと

- 通常問診の残りを続ける
- 診断候補を列挙する
- 「大丈夫」「緊急ではない」と保証する
- 119相当の状態で、長い確認質問や個人情報収集により行動を遅らせる
- #7119の対象地域・時間を確認せず、必ずつながると断定する

## 8. 否定・曖昧表現の要確認事項

**[NAOMI設計仮案] [専門家判断待ち]** 単純な部分文字列一致は採用不可とする方向でレビューする。最低限、次の軸を分ける必要がある。

| 軸 | 例 | 仮の扱い |
|---|---|---|
| 肯定 | 「胸が痛い」 | 承認済みルールに従い停止候補。 |
| 明示否定 | 「胸痛はありません」 | `胸痛`の語だけで陽性にしない。ただし他の上位確認は継続。 |
| 二重否定・弱い否定 | 「胸が痛くないとは言えない」 | 不明として確認1問またはHuman Handoff。 |
| 不明 | 「息が普通か分からない」 | 安全側にHuman Handoff。 |
| 過去 | 「昨日は息苦しかったが今は平気」 | 自動で安全判定しない。発症・持続・現在状態の承認済み確認が必要。 |
| 条件・仮定 | 「もし息苦しくなったら？」 | 現在症状として扱わず、一般情報要求として分離。 |
| 引用 | 「サイトに『胸痛』と書いてある」 | 本人症状として扱わない。 |
| 第三者 | 「母が意識ありません」 | `母`を対象者として即時Handoff候補。入力者本人の状態に誤帰属しない。 |
| 訂正 | 「胸痛です、いや胸痛はありません」 | 最終節だけで上書きせず、矛盾として確認。 |
| 誤字・音声認識 | 「いきぐるし」「むねくるしい」 | 対応語彙と誤検知の限界をテスト。曖昧時は人へ。 |

### 専門家への確認

- [ ] 高緊急度語の明示否定があった場合、他の共通確認へ進む設計でよいか
- [ ] 二重否定、矛盾、過去症状、不明回答のそれぞれで、確認1問が許される範囲
- [ ] 返答が途切れた場合、無応答を医学的異常として扱う条件と、単なる通信切断の区別
- [ ] 誤検知を減らす確認質問が、見逃しや行動遅延を増やさないか
- [ ] 第三者相談で本人のそばに行けない場合の標準Handoff文

## 9. 年齢・妊娠・既往歴・服薬の要確認事項

### 9.1 年齢

**[公式資料要約]** 公式資料では、小児用プロトコルは概ね15歳以下、高齢者は65歳以上とされる。厚生労働省ページも子どもを15歳以下として分けている。

**[NAOMI設計仮案] [専門家判断待ち]** 年齢に関する設計仮案:

- 年齢区分は緊急性を下げる材料にしない。
- 明白な緊急状態では年齢回答を待たずHandoffする。
- 15歳、16歳、64歳、65歳の境界期待値を専門家が確定する。
- 乳児、とくに月齢が重要となる範囲は、一般の年齢質問と分けて確認する。
- 年齢不明は成人扱いで続行せず、症状と応答能力に応じて人へ引き継ぐ。

### 9.2 妊娠・妊娠可能性

**[専門家判断待ち]** 妊娠に関する具体的分岐は本資料で確定しない。

**[NAOMI設計仮案]** 質問自体がセンシティブであり、性別や見た目から推定しない。

専門家に以下を確認する。

- [ ] どの主訴で妊娠・妊娠可能性の確認が必要か
- [ ] 「妊娠中」「可能性あり」「不明」「産後」の区別と、週数を聞く必要性
- [ ] 強い腹痛、性器出血、失神・強いふらつき等との組合せでのHandoff先
- [ ] 妊娠の可能性を答えたくない場合の安全な代替経路
- [ ] 未成年者や第三者相談での質問文、プライバシー、同席者への配慮

### 9.3 既往歴・服薬

**[公式資料要約]** 厚生労働省は119時に持病、かかりつけ医、普段の薬、医師の指示を伝える情報としている。

**[NAOMI設計仮案]** NAOMIでは診断推定に使わず、Handoff Noteの事実情報とする。

専門家に以下を確認する。

- [ ] 緊急度を上げる可能性がある既往歴・服薬の最小集合
- [ ] 抗凝固薬、免疫抑制状態、心肺疾患等をどの症状と組み合わせるか
- [ ] 「薬の名前が分からない」「お薬手帳がない」場合の扱い
- [ ] 既往歴なしという否定と、未確認・不明を明確に分けること
- [ ] 明白な緊急時に既往歴質問を省略し、直接119へ進む条件

## 10. 現行コードに対する観察（実装指示ではない）

現行`agent/intake_manager.py`は、回答中の固定語を部分一致で`high / medium / low`へ追加する。`agent/core.py`の`_detect_red_flag()`にも固定語と一部組合せ条件がある。

この現行ロジックは、次の点で医療承認済みルールとして扱えない。

- 「胸痛はない」「意識はある」のような否定でも語が一致し得る
- 本人、家族、引用、仮定、過去症状の区別がない
- `high`、`medical_emergency`、119、有人相談の対応関係が医学レビューされていない
- 年齢、妊娠、既往歴、服薬、不明回答を構造的に扱わない
- 現行コード内に文字化けした候補文字列があり、根拠を監査できない

Stage 1では、既存ルールをそのまま移植・拡張せず、医療レビューで承認された最小ルールへ置き換える計画を別途作る。
